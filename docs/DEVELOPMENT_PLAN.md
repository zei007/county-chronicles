## 1. 项目愿景与成功标准

**一句话**：以真实统计数据为锚的中国资源型城市兴衰互动叙事 + 模拟经营游戏，手机/电脑双端、可完全离线部署。

| 维度 | 成功标准（验收口径） |
|------|---------------------|
| 数据真实性 | 每座资源城 ≥2 个真实统计锚点（公报 GDP + 人口），来源 URL 可追溯；估算值显式标注 |
| 可玩性 | 探索/经营/对比三模式完整闭环；引擎平衡回归：放任=D、均衡=A/S、转型=S 稳定复现 |
| 双端体验 | 390px 与 1440px 双视口浏览器实测通过；触控目标 ≥36px；零横向溢出 |
| 零外网依赖 | 构建产物零外部请求（图表/地图/字体/音效全本地），离线内网可部署 |
| 工程质量 | `tsc --noEmit` 零错误；`next build` 全页面零报错；改引擎必过 balance-test、改数据必过 data-qa |

## 2. 当前状态基线（v1.1 已交付）

- **内容**：43 资源城 + 11 对照城（1939→1730 起始，覆盖煤/油/铜/铁/金/锑/镍/锡/汞/锌/铝/镁/稀土/石材/盐湖）；106 个静态页面

- **数据**：43 城全部具备真实锚点（两轮采集：batch A–E + 2026-11 batch-F 补齐新增 10 城与淮南复核）；管线脚本 8 个（convert/gen-index/merge/apply-patches/data-qa/balance-test/scan*）
- **质量**：tsc 零错误；build 106 页零报错；浏览器实测（锚点值、死链、单位、移动端图例）全部通过

## 4. v1.2 详细计划（下一版）

### 4.1 工作包 A：对照组城市经营模式（引擎适配）✅ 已交付（轻量实现）

- **交付记录（2026-11-01）**：以数据驱动标志 `simMode:"growth"` 替代 `Regime` 接口抽象（更小改动面，行为等价）——增长城无资源闸门（`resourceLeft` 恒 1、`gate=1`、`resShare=0`）、人口乘数地板 0.75、结局文案双轨（时代标杆/稳健增长/发展放缓/掉队/错失时代）。11 城经 `scripts/patch-growth-mode.mjs` 幂等写入；`/play/[key]` 扩至 54 城（构建 117 页）。balance-test 扩为 4 资源城+深圳增长用例。**顺延 v1.3**：随机事件池分流（增长城专属事件）。

- **目标**：深圳等 11 座对照城开放县长生涯，用"增长叙事"替代"资源枯竭"叙事
- **任务分解**：
  1. `simulator.ts` 抽象 `Regime` 接口：`resource`（现状，枯竭闸门）与 `growth`（新增：产业升级/土地/人口流入驱动）
  2. growth 模型参数标定：以对照城真实 GDP 轨迹为锚，偏离乘数沿用现有钳制
  3. 随机事件池分流：资源城事件（矿难/环保督察）与对照城事件（用地紧张/产业外溢/人才房）
  4. 结局文案改写（"转型典范"→ 双轨：兴城有兴城的结局树）
  5. 移除三处"对照城市 · 仅探索"门控（CityGame ×2 + 首页名片）
- **验收**：balance-test 扩展为 4 对照城 × 3 策略；深圳/喀什各实测 1 局全流程；历史事件如期出现
- **依赖**：无（纯引擎层）
- **风险**：增长模型失稳 → 复用 v2 锚定+钳制框架，先跑自动化再上线

### 4.2 工作包 B：七普人口逐城复核补全 ✅ 已交付

- **交付记录（2026-11-01）**：batch-G 补齐 10 城 `census2020`（淮北此前已有），44/44 全量覆盖；`data-qa.mjs` 增加覆盖断言（缺失即 FAIL，实测逮住淮南遗漏）。逐城来源见 `DATA_SOURCES.md §2.1`。铜陵/萍乡/双鸭山/涟源/新余为"万"口径或镜像整理值，精确到个位列入 v1.3。

- **目标**：43 城 `real_anchors.census2020` 全量落盘（当前仅部分城市有）
- **任务分解**：
  1. 逐城检索《第七次全国人口普查公报》（stats.gov.cn / 省市局镜像），核实 2020-11-01 常住人口
  2. 新 batch-G 注入；`apply-patches` 步骤 4 用七普校准 `space.peak_pop`
  3. 与 `space.peak_pop` 偏差 >5% 的城市在 DATA_SOURCES 单列说明
- **验收**：扫描脚本 `no census` 清零；data-qa 全绿
- **风险**：个别县市普查公报无在线版 → 标注"省公报分市表"来源，仍属官方口径

### 4.3 工作包 C：历史事件卡图文升级

- **任务分解**：每城精选 2~3 个关键事件配图（老照片优先 CC/PD 授权，本地化压缩 ≤100KB/张）；事件卡与档案报告引用

## 7. 质量保障体系（每轮迭代必跑）

```bash
npx tsc --noEmit                 # ① 类型检查：零错误
npm run build                    # ② 生产构建：全页面零报错
node scripts/balance-test.mjs    # ③ 引擎回归：改 simulator 必跑
node scripts/data-qa.mjs         # ④ 数据 QA：改 cities JSON 必跑
node ../../_tools/scan-data.mjs  # ⑤ 文本扫描：繁体/混排/占位符清零
# ⑥ 浏览器实测（双视口 390/1440）：新页面 + 改动的页面 + 核心流程各一遍
```

**浏览器实测清单**：首页加载 → 选城 → 探索页时间轴/锚点年数值 → 经营页开局/推进 3 年/事件弹窗 → 移动端图例与引导层 → 对照城无死链。

**数据可信分级**（写入 sources 的 desc）：
- `verified`：公报/普查原文数值（附 URL）
- `inferred`：检索汇总/推算值（注明方法）
- 未标注 = 早年插值估算，游戏内已明示

## 8. 风险登记册

| 风险 | 概率 | 影响 | 缓解 |
|------|------|------|------|
| 镜像站（tjcn/etmoc）不可达 | 中 | 数据采集受阻 | 官方统计局官网直达 + WebSearch 兜底；已采锚点固化在 verified.json，不阻塞开发 |
| 五经普修订导致口径跳变（如石嘴山/墨竹工卡） | 已发生 | 图表断崖 | apply-patches 末年续接 + 注明口径（已有先例） |
| 引擎参数改动破坏平衡 | 中 | 结局分布漂移 | balance-test 门禁 + 钳制常数改动需注释理由 |
| 新增内容使 bundle 超预算 | 低 | 移动端加载慢 | 城市数据走静态导入按页分包；图片懒加载 + 100KB/张上限 |
| 对照城增长模型失稳 | 中 | v1.2 延期 | 先自动化回归再接入 UI；必要时灰度 3 城先行 |
| 版权风险（老照片） | 低 | 下架返工 | 只收 CC/PD 素材 + 来源登记 |
